For owners of booking websites

Can an AI agent book on your site?

Agent Lighthouse sends Kane CLI to try your booking flow, measures the extra work an agent burns, proposes a fix, and proves it with fresh runs and a human-path check before you approve anything. We never change a site without the owner’s say-so.

Agents are starting to book. Most websites aren’t ready.

  • Google’s AI Mode can book restaurant tables, event tickets and beauty appointments straight from search, and ChatGPT’s agent mode can sign in to a booking site and reserve a table.li.solutions: AI booking agents

The loop, in four steps

  1. Measure

    Kane CLI books from scratch three times. Each run becomes a score and an Agent Tax: the extra steps, seconds and credits per successful booking.

  2. Diagnose

    The OpenAI API reads Kane’s failing step, its screenshot and the page, and names the cause.

  3. Fix

    Codex edits only your site’s files, on a separate branch. A scope guard undoes anything else.

  4. Prove

    Three fresh Kane runs plus a human-path run. A fix qualifies only at score 80+ and a passing human path.

You approve. By default the result is a proposal (a pull-request description with every change, the Kane failure it answers and the evidence). Automatic apply is only for sites you own and opt in.

What Kane caught

assert: a booking confirmation with a reference code is shown

Kane filed this as a confirmed product bug: “The completed free-visit form did not show a booking confirmation or reference code after it was submitted.” The confirmation was a toast that disappeared after 2.5 seconds.

On the hard-mode site, Kane cleared a newsletter pop-up, a cookie wall, a hover-only dropdown and an unlabeled calendar, then stopped at the “I’m not a robot” check: blocker.captcha. It won’t pretend to be human, and that’s a decision for the owner, not an agent.

You stay in charge

  • Propose mode is the default: the fix waits on a branch with a PR description, linked Kane evidence and the human-path result.
  • A score alone never qualifies a fix. A person’s booking must still show its reference five seconds later.
  • Every repair is its own commit naming the Kane failure it answers. Every OpenAI call is logged.

Limitations

  • The score weights are a design choice, not a validated metric. Optimal step counts are hand-counted.
  • The sample sites have planted problems and no booking backend.
  • Kane varies from run to run, and three runs per side is a small sample.
  • The repair loop only runs on sites the owner controls. External sites would get a score only, and that mode isn’t built yet.
  • The hackathon’s run-report wrapper labels passing Kane 0.10 runs “errored”, so the raw streams are in the repository for checking.
